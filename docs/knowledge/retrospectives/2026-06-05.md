## What Got Done

**Mutation follow-through (PR #71, plus test commit).** The factorial-rs `>=`→`>` sieve mutant from the June 1 mutation run was killed — a test was added that specifically exercises the boundary. The two equivalent mutations in factorial-rs and amicable-rs were excluded via `.cargo/mutants.toml`. This is the first example of the mutants.toml exclusion pattern being used in production. The mutation timeout was also reduced 120s → 30s to prevent CI timeout on equivalent infinite-loop mutations.

**Release workflow alignment (PR #72).** Math release workflows aligned with the etch-cli strategy: `workflow_dispatch` with a `version` input, tag creation in-workflow, Node.js 24, `actions/checkout@v6`. 12 files changed. This was a batch normalization; no functional change to what gets released.

**sha256sum path fix (PR #73).** Release artifacts were generating checksum files containing `target/release/<binary>` instead of `<binary>`. End-users downloading and verifying with `sha256sum --check` would get `No such file or directory` because the relative path in the checksum file doesn't match their download directory. CI bug — ships with the binary but silently fails. Fixed by `cd`ing into the binary dir before calling `sha256sum`.

**ADR catch-up batch (11 ADRs).** ADR-0011 through ADR-0021 written for decisions from April–May. This paid a documentation debt accumulated during the coverage push and velocity sprint. Notable ADRs include injectable-io-rust-cli-testability (0018), 90-percent-coverage-gate-ci (0019), dual-mode-ci-prepush-github-actions (0020), and processpool-serial-fallback (0021).

**CLAUDE.md rationalization.** Removed sections from the repo-level CLAUDE.md that duplicated content in the global `~/.claude/CLAUDE.md` (behavior, shell, rust, python standards). Repo CLAUDE.md now focuses on repo-specific addenda. Reduces maintenance surface when global standards evolve.

## Recurring Gotchas

**1. ADR debt accumulates during velocity sprints.**
11 ADRs written retroactively after a 30-day sprint (April–May). ADRs are required-by-design before or alongside implementation, but the velocity sprint outpaced the documentation. The gap was paid this period — but the pattern of catching up post-sprint is weaker than writing ADRs as decisions are made. ADRs written after the fact lack the "rejected alternatives" content that makes them valuable; they become descriptions of what was built rather than records of why.

→ **Proposed action:** add an ADR check to the `math-new-cli` skill and to `pr-review` (for any structural decision). When a PR changes algorithm, CI structure, or test infrastructure without a linked ADR, flag it.

**2. sha256sum path bug shipped in multiple release workflows.**
The bug was present across 11 release workflows and was only caught after the release workflow alignment PR (#72). The pattern (not cding before sha256sum) is documented in `~/.claude/standards/ci.md` — but that standard was apparently not applied retroactively when the workflows were created. → **No new action** — the standard exists; the fix is applied; this is a one-time correction.

**3. Mutation CI only caught on first real run.**
The mutation testing workflow had both a rust-cache error and an expression injection vulnerability that only surfaced when the workflow actually ran (June 1). The workflow was created in a prior period, tests were never run on it before commit. → **Proposed action:** for any new CI workflow, trigger it manually (`gh workflow run`) on a test branch before the PR merges.
