# ADR-0029: Release Notes Live in the Release, Not a Committed CHANGELOG

**Date:** 2026-10-24
**Status:** Accepted. Supersedes the committed-`CHANGELOG.md` part of ADR-0010.

## Context

ADR-0010 had every `release-*-rs.yml` generate the full history with git-cliff into
`<crate>/<crate>-rs/CHANGELOG.md` and push a commit of it to `master`, on a step marked
`continue-on-error: true` to absorb the no-op case.

`master` is protected: required status checks `secret-scan` and `mutation-pr`, which run only
on pull requests. A push from the release job's `GITHUB_TOKEN` cannot satisfy them, so GitHub
rejects it:

```
remote: error: GH006: Protected branch update failed for refs/heads/master.
remote: - 2 of 2 required status checks are expected.
```

The first per-crate releases on 2026-10-24 (all 11 crates at `0.1.0`, runs 40130273092
through 40135881434) each hit GH006 exactly once, and `continue-on-error` turned every one of
those steps green. No per-crate `CHANGELOG.md` has ever existed on `master`
(`git ls-files '*/CHANGELOG.md'` is empty), so the committed changelog ADR-0010 promised was
never delivered, and the step meant to deliver it reported success.

Two ways to keep a committed changelog were considered and rejected:

- **Open a PR from the release job.** A PR created with `GITHUB_TOKEN` triggers no workflows,
  so its required checks never run and it can never merge. Making it work needs a PAT or a
  GitHub App credential: a new long-lived secret held only to write a file whose content is
  already in the release.
- **Exempt the bot from protection.** Classic branch protection has no per-actor bypass short
  of dropping admin enforcement, and a release job able to write `master` unreviewed is a
  larger change to the trust model than a changelog is worth.

## Decision

Each release's notes live only in its GitHub release body, generated by the existing
`Generate release notes (latest only)` git-cliff step and passed to
`softprops/action-gh-release` via `body_path`. The `Generate CHANGELOG` and
`Commit CHANGELOG` steps are removed from all 11 release workflows.

A release step either works or fails the job: no step in a `release-*-rs.yml` may set
`continue-on-error`, and no step may run `git commit`. `tests/test_release_workflows.py`
pins both, plus `body_path` reading the release-notes step's output.

A crate's full history is reproducible on demand with
`git cliff --include-path "<crate>/**" --tag-pattern "<crate>-v.*"`, or by reading its
releases in order.

## Consequences

- No per-crate `CHANGELOG.md` in the repo; the GitHub releases page is the changelog.
- No new secret is needed; the release job keeps `contents: write` only for the tag and the
  release.
- A release that cannot do what it claims now fails visibly instead of succeeding with a
  silently skipped step.
- The root `CHANGELOG.md` is unaffected; it is maintained outside the release workflows.
